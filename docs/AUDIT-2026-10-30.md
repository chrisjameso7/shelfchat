# ShelfChat audit — 30 October 2026

## Scope and baseline
Repository: chrisjameso7/shelfchat, clean main at 4967b9b. Vercel production commit matches. This report records the pre-change baseline; implementation and verification follow in the session report.

## Architecture
React 19 + TypeScript + Vite 6, React Router, Tailwind/CSS, Lucide; native dialogs and lazy EPUB reader. Vercel serves a single Node API function, Neon Postgres owns production metadata/community, and a public Vercel Blob store holds contributed files. SQLite/Express is the local-development counterpart, not production. No account service is used. Handles/tags live in localStorage; reading progress and visitor IDs use browser storage. Server-only database, Blob, import and cron credentials are configured; their values were not exported into this report. An integration-created VITE_NEON_AUTH_URL is a URL, unused by the app, not a working author authentication system.

## Verified functionality
Production GETs returned 200 for catalog, margins and a book detail. The catalog reported 10,510 indexed titles at audit time; a discovery-only query returned no books. Jekyll and Hyde identifies Gutenberg and its licensing source. Prior real-file verification/streaming code is present. Client posting has a 15-second deadline and idempotent request IDs. Community is a separate route; database timestamps and expiry constraint enforce a 72-hour lifetime, with server filtering and daily/on-read purging. Book marginalia is separate and persistent. Presence uses actual recent visitor UUID heartbeats; activity records originate in real download/contribution/note actions. No seeded community posts or fake online counters were found.

The baseline suite passed 39/40 in a busy parallel run: the isolated server startup exceeded 15 seconds. Rerunning that integration test alone passed. npm audit --omit=dev found zero vulnerabilities. This is a test-harness timing issue observed here, not evidence that every production interaction was exercised today.

## Partial or missing functionality
- Identity tags are unnecessarily mandatory. Browser handles are not owned or verified and can be impersonated.
- Search uses a full-text index but defaults to newest rather than relevance. Collection options are hardcoded even when empty. Catalog total is the global indexed count, not a filtered match count.
- Covers are generated typography, not necessarily original covers. Rights assertions exist in harvested records but are not fully surfaced on detail pages. Language and rich subject fields are not reliably recorded.
- Reports, moderation queue, submission review, author ownership/profiles/workspace, private unpublished-file storage, related-title discovery and meaningful author analytics are missing.
- Community disappearance is server-enforced at 72 hours; physical deletion is subsequent on-read/daily cleanup. Backups are not erased per-post at that boundary.
- No billing, sponsored placements, payment verification or commercial distribution exists. None should be advertised.
- There is no verified legal contact or operator name yet; founder confirmed these are not available.

## Security and privacy findings
- New contributions immediately publish after a rights checkbox and file-signature check. Neither proves distribution rights; the existing Blob store is public. Unpublished author files must not use this path.
- RLS is enabled with server-owned access, not per-user author tenancy. That is appropriate for current public endpoints but insufficient for a private author workspace without additional authorization.
- Public write rate limiting exists. Presence UUIDs can be forged, so counts are approximate, not verified people. Presence and rate-limit rows need routine pruning.
- Activity can expose a handle's association with a book note; avoid presenting public individual reading histories or copying community text into permanent logs.
- Signature checks and bounded reader validation reduce malformed-file risk but are not malware scanning or proof every page renders.
- EPUB streaming restricts known providers and validates redirects; this safeguard must remain intact.

## Cost and operational risks
Production polls at 10–30-second intervals, which can keep a free Neon database awake. Imports run on a local checkpointed worker, not a durable hosted service. Current importer advanced beyond 10,000 real records; its job is not a guarantee of 20,000 or 75,000 readable titles. Existing audit finished an earlier 5,604-record slice with 156 uncertain source checks; this does not validate every current file. External sources can change or block downloads. Database capacity estimates are extrapolations, not provider guarantees. Backups/restores, abuse-response coverage and load limits are not verified operationally.

## Implementation order
1. Stabilize optional identity, honest presence, bounded polling and correct discovery/ranking/metadata labels.
2. Add reports, authenticated operator moderation, policy pages matching actual behavior, and a publication gate for new submissions. Preserve existing published books.
3. Refresh the actual library, detail, community and submission interfaces with shared tokens/accessibility; show only populated collections.
4. Verify local/API/database behavior, migrations, deployment and mobile flows. Document rollback and limitations.
5. Only then implement owned author workspaces/private storage and validate demand. Payments and subscriptions remain explicitly deferred.

## Decisions and credentials
A public legal/contact identity is still needed before a broad launch. Private unpublished file storage and durable author ownership are prerequisites for the author platform. No paid-plan upgrade or new recurring paid service is authorized or needed for the core pass. In-app reports can operate now; formal legal compliance and round-the-clock moderation cannot be claimed.
